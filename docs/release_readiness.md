## 二、F8 真按验证（本轮）

### 2.1 构造方式

引擎级「正在点击」的任务今天构造不出来（原因见 2.4），所以用**调度器带一条 15 分钟后开卖的占位任务在跑**来验证停止链路：这条任务处于「等开卖」空转，是真任务、真队列、真线程。

### 2.2 按前 / 按后状态

| | 按 F8 前 | 按 F8 后 |
|---|---|---|
| 调度器 `running` | `true`（启动 **28 ms** 后置位） | `false`（**62 ms** 内） |
| `engine.state` | `idle`（等开卖，未进 SCAN/WATCH） | `idle` |
| 占位任务 `248b4800` | `pending`（900s 后布防） | `pending`（未布防，未被触发） |
| 光标 | `(960,540)` | `(960,540)`（3 秒后仍不变） |

### 2.3 日志行（原文）

```
05:27:29  调度器已启动
05:27:29  执行模式：实战
05:27:29  下一条：F8验证占位，900s 后进入布防
05:27:30  钩子收到 F8
05:27:30  收到停止热键
```

- F8 注入时刻：启动后 **+1.554 s**
- 停止耗时：**62 ms**（F8 → `running=false`）
- 停后 3 秒：新增日志 **0 条**，含「点击/注入/购买/移动」字样 **0 条**，三帧整帧差 **0.493 / 0.504**（只有 HUD 呼吸动画），光标零位移 → **之后没有任何注入**
- 收尾：占位任务已删；两条被上一轮跑挂的任务已复位 `pending`；`env.preflight` 开关已复原

### 2.4 这一格的边界（必须写清）

- **悬浮窗/控制台这次显示的是「空闲 / idle」，不是「已暂停 / paused」。** 原因是引擎没进过 SCAN/WATCH：`engine.stop()` 只有在引擎处于运行态时才把状态置 `abort`（映射到悬浮窗「已暂停」），空转态停止就停在 `idle`。
- 引擎起不来的根因是**自动标定必然 fallback**（离线复算当前画面）：
  - `buy` 命中分 **0.702**，但偏移 **+66 / +31 px**，超出可信上限 **24 px** → 判 `fallback`；
  - `confirm` 最高分 **0.223**（阈值 0.55），当前页面根本没有确认弹窗。
- 所以要补「引擎在跑 + 悬浮窗已暂停」这一格，只有两条路：**把游戏停在确认弹窗上**再点一键自动标定，或者**在区域微调里手框一次**购买/确认区域。两条都动游戏，本轮按你的要求没做。

## 四、已知风险

1. **OCR 单帧 1765 ms**：整帧识别一次要 1.7 秒，抢购窗口内只能做约 1 次「识别 → 决策 → 点击」。热卖商品在开卖瞬间基本没有二次校验的机会；这也是影子测试只敢做几何校验、不敢做实点击的原因。
2. **价格 token 粘连**：相邻两列价格在低对比度下会粘成一串（如 `118,888120,000`），现在靠按 x 聚类拆列；拆错就会把单价读成双倍，直接导致买错档位。
3. **余额只能靠弹窗字符串判**：没有数值接口，只能读支付弹窗里的文字。OCR 读不到 = 余额未知，脚本不能据此决定「买不买」，只能事后记一笔。
4. **交易时段 08:00–次日 05:00**：窗口外页面仍可浏览，但购买/确认无效，脚本不判断时段；在窗口外跑只会有「无响应」，容易被误判成点击配方失效。
5. **自动标定对版式敏感**：当前版式下 `buy` 偏 66/31 px 就判 fallback，说明内置坐标只对某一种分辨率/UI 缩放成立；换机器、改 UI 缩放、换语言都会重演。
6. **单击无效是平台特性**：UE5 按钮对单次按下抬起判定过严，单击 diff 只有 0.23–0.35（等于没点），双击 diff 48.52 才打开面板。脚本侧已固化为默认双击配方（见下），但这是「对抗 UI 时序」，不是稳定契约。

## 五、现在四处空白

### 空白 1：余额门槛

- 当前余额 **2,049**；三页签实测最低可买：挂饰 **5,201**、曼德尔砖 **10,665**、枪皮 **118,888**。
- 要成交任意一件，最少还差 **5,201 − 2,049 = 3,152**。
- 结论：**在充到 5,201 之前，整条成交链路无法端到端验证**，所有「已通过」都只到「点开挂单面板」。

### 空白 2：真机自拉起闭环

- `core/gpu_guard.py` 的 `launch_game → wait_window → 回大厅 → 续跑` 只在假 launcher + 假 finder 上跑通过。
- 真机没有触发过一次 TDR 自恢复；恢复预算（≤2 次）在真机上还没花过。
- 需要的验证：真实触发一次窗口消失（或手动结束进程），看是否 ≤2 次内拉回、第 3 次是否按文案停。

### 空白 3：成交留证

- 现在只有日志字符串，没有「成交截图 + 订单/挂单编号 + 时间戳 + 单价」的落盘证据。
- 缺这一块，售后无法证明「脚本确实买到过」，也无法复盘买贵/买错。

### 空白 4：画质抑制 TDR 的建议值

- 建议：**中低画质 / 关光追 / 锁 60 fps**。
- 这是经验值，没有实机 A/B：未验证这三项能否把 `nvlddmkm 153` 从 4 次降到 0 次。
- 建议在装机说明里写成「推荐设置」，不要写成「已验证可消除 TDR」。
