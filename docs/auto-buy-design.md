# 全自动购买设计

用户勾选目标（武器 / 磨损上限 / 价格上限 / 买几件），程序自己去交易行把它买回来。
现状：程序能做到「列表已经在屏幕上时，挑符合条件的买」（`engine.py:265-405`）。
缺的是**把界面操作到那个状态**，以及**买入失败后的处理**。

本文件记录设计决策与未验证项。**未验证的环节必须先做演练，不许直接实战。**

## 二、每步的失败模式与处理

设计原则：**任何一步不确定就停，并把界面留在可人工接手的状态。**
买错东西的代价远高于没买到。

| 步 | 失败模式 | 处理 |
|---|---|---|
| ① | 不在一级菜单（在局内/设置里） | 停，提示「请先回到大厅」 |
| ② | 标签位置变了 | 模板匹配不到就停，不盲点 |
| ③ | 目录里找不到目标武器 | **滚动到底仍找不到则停**，报「目录里没有 X」；不要继续往下走 |
| ④ | 点目录项后没进列表页 | 超时停 |
| ⑤ | 价格输入框没聚焦，输入的数字落到别处 | 点输入框后**截图确认出现光标**再输入 |
| ⑤ | 筛选面板展开/收起状态与预期不符 | 先判断面板是否已开，再决定点不点「筛选」 |
| ⑥ | OCR 读不出价格 | 该行跳过（已有行为，`market.py:135`） |
| ⑦ | 没有任何一条符合条件 | **翻下一页**（见第四节），翻完仍无则停 |
| ⑧ | 点了购买但没弹确认窗 | 已有超时处理（`engine.py:476-478`） |
| ⑨ | **余额不足** | 立刻停，**绝不点「充值」** |
| ⑨ | 商品已被别人买走 | 退回列表换下一条 |

## 三、必须新增的安全设施

1. **余额不足弹窗处理**（实测存在）
   录屏 37.5 秒实测：「您当前的三角币不足，是否前往充值？」，弹窗有「取消」和「充值」两个按钮。
   **程序只允许点「取消」**，然后停止并报告。点「充值」会花真钱，属于不可逆操作。

2. **筛选状态标记**
   筛选应用后按钮显示「已筛选 1 项」。程序开始前应检查是否已有残留筛选
   （上次失败留下的），有就提示用户先清掉。

3. **买错保护**
   点进详情页后、点购买前，**再确认一次详情面板里的商品名与价格**符合条件。
   列表页的 OCR 可能出错，详情页信息更完整（含精确磨损值）。

4. **购买次数上限**
   单次运行最多买 N 件（用户设定），防止筛选条件写错时连续买入。

## 四、未验证项（必须先实测）

以下三处在录屏里**没有出现**，坐标与行为均未知：

| 项 | 为什么未知 | 怎么验证 |
|---|---|---|
| **左侧目录滚动查找** | 录屏里操作者是手动滚动到 QBZ95-1 的，程序要自己滚。目录项位置随滚动变化 | 需要真机：滚动一次、截图、看目录项位移多少像素 |
| **翻页** | 录屏全程「第 1 页」，没点过下一页 | 需要真机：点一次下一页，确认箭头坐标与页码变化 |
| **筛选面板的选项坐标** | 录屏里只改了价格，没勾稀有度/成色/材质 | 需要真机：逐项点开，记录坐标 |

**这三项没有真机数据就是在猜。** 猜错的表现是点到别的选项，可能导致筛选出错误列表然后买错东西。

## 五、实施顺序

按风险从低到高，每步做完都能独立验证：

1. **价格筛选自动化**（步⑤）—— 已被录屏证实可行，且只改一个数字输入框，风险最低
2. **余额不足弹窗识别**（步⑨）—— 纯识别 + 停止，不新增点击
3. **详情页二次确认**（步⑦⑧ 之间）—— 加固现有链路
4. **目录查找 + 翻页** —— 需要真机测绘坐标后才做

前 3 步**不需要真机也能开发**（用录屏帧当输入验证识别逻辑），第 4 步需要用户在游戏里配合测绘。

## 六、与现有代码的接缝

- `engine.py:265` `_execute_list` 是「列表已就位」之后的全部逻辑，**不改**
- 新代码放在它之前，作为「把界面带到列表页」的前置阶段
- 前置阶段复用现有的 `Screen` / `Mouse` / `match` / `template` 设施
- 新增的坐标（市场入口、标签、筛选按钮）走 `config.py` 的 `regions` 模式，
  **可框选、可重配**，不硬编码 —— 游戏更新后用户自己重框即可
