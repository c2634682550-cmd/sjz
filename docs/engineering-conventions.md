# 工程约定

## 1. 省判定 / 省动作的改动，必须先写反证用例

**背景（2026-11-08）**：`go_to_onsale` 合并重复判页时，从代码推出
「`enter_market` 返回 onsale 等子页时不需要 `recover()`，直接点
『典藏外观』标签即可」。台架全绿，真机 3/3 失败——在售页点标签，绿框
一直停在 mandel，三次都切不过去。代码层面的等价关系，在游戏里不一定
成立。

**规则**：

1. 凡是「省掉一次判定 / 省掉一次动作」的改动，提交前必须写一条**反证
   用例**，明确写出「如果这个假设错了，会看到什么现象」。
2. 真机第一次跑，按反证用例里写的现象逐项核对；不是「链路跑通了就算
   过」。
3. 反证用例进 `tests/`，docstring 保留现象描述 + 实测日期 + 复现次数，
   便于以后翻案时直接对上号。
4. 真机证伪时，先回退被证伪的那个假设，再谈优化。不许用调断言、调
   超时、放宽阈值的方式把它糊过去。

**模板**：

```python
def test_xxx_assumption_holds():
    """反证：如果 <假设> 不成立，会看到 <现象>。

    实测：<日期>，<N>/<N> 复现：<现象原文/日志片段>。
    """
```

参照用例：
`tests/test_nav.py::test_go_to_onsale_recovers_from_subpage_using_enter_market_page`
（假设「在售页可以直接切『典藏外观』标签」，真机 3/3 证伪）。

## 2. 性能断言的数值必须写出来源

台架里的耗时断言不许只写一个魔数。注释里要写清这个上限由哪几段构成
（哪几次点击/等待/轮询，各自的 timeout），否则下次没人敢动它，也没人
知道它是不是在糊。参照 `perf/bench/poll_bench.py::part_d`。

## 3. 给某个页型开快判路径，先攒够该页型的真实帧

**背景（2026-11-08）**：判页改两段式（局部 ROI 快判 + 整屏兜底）。真机
帧只覆盖 market / onsale / filter_collection，**没有 detail 帧**。用户
定死：detail 强制走整屏，帧不够就不许开。

**规则**：

1. 想给某个页型开快路径，先抓该页型的真实帧：**单页型 ≥5 帧、整批
   ≥40 帧**，覆盖该页型的主要变动（列表有/无数据、面板开/合）。
2. 同一批帧上局部判与整屏判必须**逐帧逐项一致**；不一致的帧要能解释
   （哪个锚点没落进 ROI）。解释不了就不许开。
3. 局部判的**降级率**（局部判不出 → 退回整屏）> 30%，说明 ROI 选错，
   回去重选，不许硬开。
4. 放行写成**显式映射**（页型 → 是否允许），不许默认放开、靠黑名单
   兜底。表里没有的页型一律降级。
5. 局部判与整屏判结论冲突时**以整屏为准**，并写日志 + 计数；每次判页
   都要记录走了哪条路径、为什么降级，供事后统计。
6. 局部 ROI 看不见的页面上层（弹窗、浮层）要单独加守卫 ROI；守卫的
   假设写成反证用例（参照
   `tests/test_nav.py::test_where_fast_assumption_popup_outside_guard_roi_would_misjudge`）。

参照实现：`core/nav.py` 的 `_ROI_FAST_TOP / _ROI_FAST_PAGENO /
_ROI_FAST_POPUP` 与 `NAV_DEFAULTS["fast_det_pages"]`。
